# M16 with Masterkey — playable prototype

Choose **M16 + Masterkey** under **Assault rifles** in a custom class and equip
it for your next spawn. The mounted shotgun is part of that gun, so it uses no
second inventory slot. **B** on keyboard or **D-pad down** with the updated
Peace controller config runs `weapalt`. Fire and reload use their usual buttons;
Y still swaps inventory slots. D-pad down replaces the old gesture binding.

For a quick baseq3 test, enter `exec m16_test` in the console. It starts the
ladder map with this rifle and a SPAS, binds the mode toggle, and selects the
test loadout. It does not overwrite any saved custom class. Select your regular
class afterward to restore your next-spawn loadout.

This pass uses original, basic geometry and animations, reused game shot sounds,
and prototype timings. The rifle currently fires automatically, **not the
retail M16's three-round burst**. Retail timing, recoil, detailed textures and
polished hand animation are later tuning work. It is not an imported MW2 asset.

- Rifle: 30 rounds, 120 reserve, magazine reload.
- Masterkey: 4 shells, 16 reserve, pump after a shot, individual shell loading.
- Fire during a shell reload closes the reload naturally. Releasing the trigger
  before it is ready does not queue a shot.
- Mode selection uses the existing holster and raise path. Ammo, reload notes,
  pump debt and readiness remain in shared simulation. No special NAC detection,
  scheduled scope flash or zero-duration holster was added.
- Both ammo pools, the selected mode and pump debt follow the inventory instance
  through drops and pickups. Two copies have separate pools. Matching pickups
  scavenge reserves without refilling either magazine.

`assets/source/m16/weapon.json` owns the shared timing/ammo constants and animation
lengths. `dev/tools/build_m16.py` generates the two IQM view variants, MD3 world
variants, sight/clip files, textures, icon, shader and `bg_m16_data.h` using the
Python standard library. Both variants show the attached shotgun; the active
mode places its muzzle tag on the correct barrel. The Masterkey has a weighted
pump, support hand and shell. Run the exporter with `--check` for a read-only
freshness check, then `python dev/tests/m16_asset_test.py` for independent mesh,
rig, clip and transition validation.

`dev/tools/test-masterkey.ps1` boots an isolated local game and checks rifle fire,
the mode switch, pump and one-shell reload, with screenshots. Use
`-Renderer opengl1 -VmMode 2` to check the frame-only/QVM path too.
`test-m16-viewmodel.ps1` is a separate static art preview using `testgun`.

This adds protocol **87**, game **-16**, for per-slot underbarrel ammo and dropped
gun metadata. Rebuild the executable and all modules together. IDs are appended:
M16/Masterkey are 18/19 in baseq3 and 21/22 in missionpack. Existing weapon and
saved-class IDs are preserved.
