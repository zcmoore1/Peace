# M300 Praetorian

Select **Sniper** in Class Select, or choose **M300 Praetorian** in either gun slot in
Create Class. The old Scout preset index is reused so saved custom-class
indices do not shift; the railgun remains available in Create Class.

This is original, stylized M40A3-inspired artwork: olive composite stock,
heavy barrel, dark metal receiver, integral scope, moving bolt and gloved arms.
The in-game name is **M300 Praetorian**. The artwork takes its visual cues from
the classic M40A3; internal `WP_M40A3` and `m40a3` asset paths remain stable.
No extracted Call of Duty models, textures or sounds are included.

## Initial tuning

- Five-round magazine, 30 reserve. Hitscan bullet, 100 base damage before the
  existing armor/powerup rules. It is not a rail beam or penetrating rail shot.
- 950 ms shot/bolt cycle, with action opening at 160 ms and closing at 780 ms.
- Per-round reload: 500 ms opening, 450 ms per round, 500 ms closing. The round
  seats at 300 ms of its insert segment. Reload always restarts; ammo only
  changes at shared notes, never because a picture played.
- 500 ms holster, 650 ms ordinary draw, 1600 ms first draw/check.
- 250 ms quick drop and quick raise (MW2's Intervention): the drop for a
  grenade and the return after a knife or a grenade.
- Separate 220 ms sprint entry, 640 ms loop, 260 ms exit.
- 300/200 ms ADS in/out; scope FOV is 0.26 of hip FOV. Stationary ADS has zero
  spread; hipfire, movement and airborne penalties use the shared spread code.

These are initial game-feel values, not a claim of exact CoD timings. Edit
`assets/source/m40a3/weapon.json` and run `python3 dev/tools/build_m40a3.py`.
The same source generates gameplay constants, clip lengths and sight settings.
The exporter needs only Python's standard library and supports `--check`.

## Integration

The rifle adds data to the existing fire/bolt/reload runner. It does not alter
the ordering of notes, holsters, pending ammo fills, YY, equipment recovery or
ladder transitions. First draw and all non-reload clips use the generic sprint
retention owner. No named-glitch detection, latency requirement or special
cancel window was added.

Weapon and ammo drops use the same instance/pickup code. The scope is integral;
the supported-attachment catalog prevents a global red-dot preference from
creating a visually nonexistent M40 variant. Other supported attachment masks
are unchanged.

The `.sights` `scope` directive is generic. The viewmodel aligns with the ocular
during ADS entry, then the full-screen scope replaces it at full aim. The
animation layers continue advancing while hidden. The mask is aspect-correct,
draws during killcam playback and remains with the normal HUD disabled.
Scope presentation never grants ADS, firing or reload permission.

The same `scope_overlay` field in `weapon.json` writes that `scope` line and
`M40_SCOPE_OVERLAY` in `bg_m40a3_data.h`, read by `BG_WeaponScopeOverlay`. As in
MW2 (`adsOverlayReticle`), no knife starts while such a gun is aimed; the press
is lost. That rule, with the use/reload fake reload, is the wild scope
(`dev/FAKE_RELOAD.md`). MW2's scoped snipers have `rechamberWhileAds 1`, so the
bolt stays scoped and, with aim held, the knife stays refused through it.

Protocol **75**, game version **-5**: rebuild client, server and all native/QVM
modules together. `STAT_UNCHAMBERED` now has the same full-width network encoding
as `STAT_WEAPONS`; otherwise basegame gun ID 15 would be sign-extended and
missionpack gun ID 18 would lose its chamber debt on correction.

## Art provenance

Model/rig/animations, reticle, silhouette icon, muzzle-flash geometry and shot
sound are authored by `dev/tools/build_m40a3.py`. Each mesh surface is split
below GL1's 1000-vertex limit. Runtime assets are under
`assets/baseq3/models/weapons2/m40a3/`, with the shader in
`assets/baseq3/scripts/peace_m40a3.shader` and sound under
`assets/baseq3/sound/weapons/m40a3/`.

`assets/baseq3/models/weapons2/m40a3/materials.jpg` is an original texture made
with the built-in image generation tool, then JPEG-encoded for the game.
Its generation prompt was:

> Use case: stylized-concept. Asset type: diffuse material texture atlas for an
> original low-poly scoped M40A3-style rifle in an FPS game. Create a square
> 1024x1024 flat, evenly lit material atlas, divided into four EXACTLY equal
> quadrants with straight boundaries at x=512 and y=512, zero gutters. Upper
> left: muted olive drab green molded fiberglass/polymer stock surface, fine
> stipple, understated tiny worn flecks and organic olive tonal mottling.
> Upper right: dark charcoal parkerized steel, fine grain, subtle linear
> machining scratches, mostly dark gray but readable. Lower left: dark tan
> woven sleeve canvas, tightly woven textile with subtle irregular fibers,
> no folds. Lower right: near-black rubber/glove microtexture, small organic
> grain. Every quadrant is an evenly filled flat material swatch viewed
> straight on, no lighting gradients, no bevel, no object, no gun, no borders,
> no lettering, no logos, no shadow. Restrained realistic material details
> that remain believable at game scale, not large damage or heavy grunge.
> This is a UV material atlas, NOT a picture of a rifle.

## Verification

Run `sh dev/tests/run-sniper.sh` (also with `SNIPER_TEST_FLAGS=-DMISSIONPACK`),
`python3 dev/tests/m40a3_asset_test.py`, and the existing loadout, pickup,
sight, SPAS reload, ladder, S&D and replay suites. CI checks generated assets
and builds native and QVM modules. Sniper checks include early-stow chamber
debt, note-boundary cancellation, ammo conservation, same-update YY firing,
interruptible first draw and transfer of dropped rifle payloads.

Manual playtest: select Sniper, ADS, shoot/bolt, top up one or more rounds,
sprint-Y during draw/bolt, sprint-YY, interrupt first draw, grab a ladder,
then die and pick up the rifle. Repeat while spectating and in a round-winning
S&D replay. Art should be judged with the user's full game assets; the local
headless test pack omits retail player models and some HUD textures.
